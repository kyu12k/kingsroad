# ⚔️ 말씀 대결 — 구현 계획 (초안, 2026-10-13)

> 퀴즈퀴즈 계시록 세션의 기획(실시간 1:1 암송 대결)을 킹스로드 구조에 맞춰 다시 정리한 것.
> **1단계(도전장) 구현 10/13, 배포 전.** 실시간(2단계)은 아직.

## 1단계 구현 메모 (10/13)

- 입구: 친구 창 맨 위 「⚔️ 말씀 대결」 · 친구 줄마다 ⚔️ · 홈 「오늘 할 일」의 📨 도전장 n(⚔️는 길드 출석이 이미 씀)
- 상대 고르기 = 친구 + 같은 길드원. 고르면 `battleCheck`로 먼저 확인(구글 연동·관계·열린 도전장·하루 10장) — 문제를 다 풀고 나서야 거절되지 않게
- 문제는 보내는 쪽 폰이 만든다(`makeQs`) — 7문제 = 순서 2·빈칸 2·주소 2·다음 어절 1, 안 되면 다른 형식으로. 22장 × 300번 돌려 규칙 위반 0
  - 보기는 그 장의 다른 어절에서, 끝 글자(조사)가 같은 것 먼저, **그 절에 이미 나오는 말은 뺀다**(18:13 물건 목록)
  - 주소·다음 어절: 그 장에 앞 3어절이 같은 절이 있으면 안 냄(후렴). 다음 어절은 앞 p어절(2~6)이 그 장에서 하나뿐인 길이로
  - 순서 맞추기: 5~7어절 토막에 같은 말이 두 번 있으면 안 냄(7장 지파)
- 제한 시간: 순서 30초 · 빈칸·주소 15초 · 다음 어절 12초. 틀리면 정답을 보여 준다
- 하루 10장은 서버 `rate_limits`의 24시간 창(달력 하루가 아님)
- 틀린 절 「✍️ 백지로」 = 그 절 하나 백지 판(열매 먹기와 같은 길, 진짜 백지 기록)
- featLog `bt_open`·`bt_write`·`bt_send`·`bt_play`·`bt_done`·`bt_rev`
- 아직 영어 문구 없음(한국어만)

## 정한 것 (10/13 사용자)

- **장을 정해서** 겨룬다. 「둘 다 외운 절」로 고르지 않는다 — 왜 그 절이 나왔는지 알 수 없어서 애매하다
- **링크로 초대하지 않는다** — 링크는 위험해 보여 꺼려질 수 있다. 앱 안에서 친구·길드원·태그로 보낸다
- **구글 연동한 사람끼리만** — 연동률을 높이는 계기로. 승패 기록이 계정에 남는다는 이유로 안내
- **승패 기록만** 남긴다. 보석·리그·지파 점수에는 넣지 않는다
- 이름은 **말씀 대결**, 도전장은 **하루 10장까지**
- 실시간 대결은 도전장(유령)과 **규칙·입구가 달라야** 한다 — 아래 「두 가지 대결」
- 장을 고를 때 **아무 상태도 보여주지 않는다**(내 것도 상대 것도) — 진도가 보이면 부담

## 두 가지 대결

| | ⚔️ 도전장 (유령) | ⚡ 지금 대결 (실시간, 2단계) |
|---|---|---|
| 언제 | 아무 때나 보내고 상대는 7일 안에 | 둘 다 지금 앱을 켜 두었을 때만 |
| 입구 | 친구·길드원 목록의 ⚔️ | 접속 중인 친구 옆에만 뜨는 ⚡, 상대가 30초 안에 수락 |
| 점수 | 둘 다 끝까지 풀고, 문제마다 맞힌 쪽(둘 다면 빠른 쪽) | 먼저 맞힌 사람만, 맞히는 순간 다음 문제 |
| 틀리면 | 그 문제를 놓칠 뿐 | 그 문제에서 빠짐 |
| 상대 모습 | 지난 기록이 시각에 맞춰 재생 | 상대 진행이 실시간으로 |

도전장을 보냈는데 상대가 들어오면 실시간으로 바꾸는 방식은 쓰지 않는다(입구를 처음부터 나눈다).

## 실측 (10/13)

- 하루 실제 암송한 사람 15~26명(백지·빈칸 시도 기록 기준, 일반 스테이지만 한 사람은 빠짐)
- 5분 칸으로 나누면 2명 이상 동시에 있던 때 **24%**, 5명 이상은 거의 없음, 최고 6명. 붐비는 때는 13~16시·21~22시
- 지난 14일 실제 암송 59명 중 구글 연동 35명(59%), 사흘 이상 한 31명 중 25명(81%)
- → 무작위 매칭은 지금 성립하지 않는다. 받는 사람이 **나중에** 푸는 도전장이 주로 쓰일 것

## 한 판의 흐름

1. A가 친구 목록·길드원 목록·태그 찾기에서 상대를 고르고 장을 고른다
2. A가 바로 7문제를 푼다(기록됨)
3. B에게 푸시 「○○님의 도전장 — 18장」 + 홈 「오늘 할 일」에 「⚔️ 도전장」
4. B가 열면 **같은 문제**를 A의 기록과 겨룬다. 화면 옆에 A가 그 시각에 맞힌 게 뜬다
5. 결과는 양쪽에. 진 쪽에 「다시 도전」. 틀린 절은 「이 절 백지로」로 이어진다
6. 7일 안에 안 열면 사라진다

## 문제 형식 (퀴즈퀴즈 코드를 복사해서 옮김 — 퀴즈퀴즈 저장소는 건드리지 않는다)

| 형식 | 원본(퀴즈퀴즈 `app/public/js/`) | 제한 시간(안) |
|---|---|---|
| 순서 맞추기 — 7어절 초성 카드 | `common.js` `chosung`·`roCut`·`roCards`, `scoring.js` `roRight` | 25초 |
| 빈칸 고르기 | `common.js` `tokenSpans` | 12초 |
| 주소 4지선다(같은 장) | `scoring.js` `raQuestion`, `common.js` `raOrders` | 12초 |
| 다음 어절 고르기 | 새로 | 10초 |

- 원본이 ES 모듈이라 battle.js 안의 평범한 함수로 바꿔 옮긴다
- 출제 원칙: 후렴 절(2·3장 「귀 있는 자는…」)은 주소·다음 어절에서 제외, 7장 지파 절(5~8절)은 순서 맞추기에서 제외, 초성 카드에서 기호 제거
- 본문은 킹스로드 `bibleData`를 쓴다. 15장처럼 절이 적은 장도 7문제는 나온다(제외된 형식은 다른 형식으로 채움)

## 데이터

**Firestore `battles/{id}`** — 쓰기는 전부 함수로(규칙 `write: false`), 읽기는 두 사람만(`uids`)
```
{ ch, qs: [{ k: 'ro'|'bl'|'ra'|'nx', v: '18-12', ... }],
  from: { uid, tag, nick }, to: { uid, tag, nick }, uids: [a, b],
  runs: { <uid>: [{ ok, ms }] },   // 문제마다 정답 여부·걸린 시간
  state: 'open' | 'done' | 'expired', win, createdAt, expiresAt }
```
- 승패 합계는 `leaderboard/{tag}`의 `battleW`·`battleL` — **서버 전용 필드**(`serverOnlyKeys`에 추가)
- 저장본(`kingsRoadSave`)에는 넣지 않는다 → `_mergeSaveProgress`·색인 제외 손볼 일 없음

**Realtime Database `live/{battleId}`** (2단계, 실시간일 때만)
```
{ on: { <uid>: true },            // onDisconnect로 지움
  i, startAt,                     // 지금 문제 · 서버 시각
  first: { <i>: { uid, at } },    // 먼저 맞힌 사람 — 트랜잭션(값 있으면 포기)
  out: { <i>: { <uid>: true } } } // 틀리면 그 문제에서 빠짐
```

## 서버 함수 (kingsroad, asia-northeast3)

- `battleCreate(toTag, ch, qs)` — 보낸 사람 **구글 연동 확인**(토큰 `firebase.identities['google.com']`), 받는 사람도 연동했는지, 친구·같은 길드·태그 확인, 두 사람 사이 열린 도전장 하나까지·하루 10장까지 → 문서 생성 + 받는 사람에게 FCM(`leaderboard.fcmToken`)
- `battleSubmit(id, run)` — 제 몫 기록. 두 기록이 다 모이면 승패 판정(문제마다: 맞힌 쪽, 둘 다면 빠른 쪽) → `battleW`·`battleL`
- (매일) 기한 지난 도전장 정리

## 암송 기록과의 관계

- 대결 결과는 **백지 레벨·기름 단계·복습 단계에 넣지 않는다** — 4지선다·순서 맞추기는 알아보기지 떠올리기가 아니다
- 일지(`recall_log`)에는 `mode: 'battle'`, `tr`로 남긴다(연구 재료)
- 이용률은 featLog `bt_send`·`bt_play`·`bt_live`로 잰다

## 걸리는 점

- 구글 로그인은 카카오톡 등 앱 안 브라우저에서 막힌다 → 그 환경이면 「브라우저나 설치한 앱에서」 안내(`_googleBlockedBrowser`)
- 본문이 game.js에 다 있어 정답은 숨길 수 없다. 친구끼리 승패 기록뿐이라 폰 채점으로 충분. 순위·보상을 걸게 되면 서버가 출제·판정해야 한다
- 비동기 대결의 「걸린 시간」은 각자 폰에서 잰다(문제가 뜬 순간부터) — 기기 성능 차이가 조금 섞인다

## 10/13 — 순서 맞추기를 보스전 「어려움」처럼
- 사용자: 초성 여러 개를 조합하는 문제가 단번에 파악하기 힘들다 — 킹스로드 하던 사람들이 익숙한 모양으로. (첫 글자를 보여 주는 안은 「그런 문제가 아니다」로 되돌림)
- → 보스전 어려움과 같은 손놀림: 빨간 초성 블록(가나다순)을 눌러 위 칸에 차례로 놓고 「⚔️ 공격」 → 칸마다 초록·빨강, 시간(30초) 안이면 놓은 블록을 눌러 되돌리고 다시 공격 · 다 맞으면 블록이 단어로 바뀐다.
- 채점은 칸마다 초성끼리(초성이 같으면 어느 쪽이든 맞다). 기호는 빼고 보인다(퀴즈퀴즈 원칙 — 보스전은 쉼표가 남는다).

## 10/14 — 순서 맞추기 난이도 낮춤
- 사용자: 초성 조립 난이도를 낮추자 — 초성이 아닌 단어로, 빈칸이 대략 어느 정도 길이인지 알 수 있게.
- → 블록은 단어(파랑, 보스전 「보통」 빛깔) · 위 칸엔 자리마다 **그 자리 단어 길이만큼의 빈칸**(다음 자리 금빛)을 미리 그려 몇 단어·대략 몇 글자인지 보인다 · 놓은 블록은 앞에서부터 채움 · 공격하면 칸마다 초록·빨강(그 자리 단어면 맞음).

## 10/14 — 「✍️ 백지로」가 망각의 고난으로 잡히던 것
- 사용자: 도전장에서 틀린 절을 백지로 했더니 망각의 고난이 클리어된 것처럼 됐다. `battleReviewVerse`가 열매 먹기와 같은 길(`startHardshipSession('memory', [id])`)을 쓰면서 「끼워 넣은 판」 표시를 달지 않아 진짜 망각의 고난(기록·일일 미션·승점)으로 셌다.
- → `_pendingHardshipEmbed = { battleRev: id }` · `hardshipState.battleRev` — 열매·나눔 열매처럼 `_isEmbeddedBlankSession`·이어하기 제외·망각 기록 제외에 넣고, 승점 0(`nr_battle` 「⚔️ 대결 복습 — 승점 없이 백지 기록만」), 일지 맥락 `battle`. 백지 레벨·복습 기록은 평소대로 남는다(진짜 백지 시도).
